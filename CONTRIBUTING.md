# Contributing to Mintforge UI

Thank you for your interest in contributing to **Mintforge UI**, an open-source UI ecosystem developed by **NEXYOUTH**.

We welcome contributions from developers who want to improve reusable UI components, design systems, documentation, and developer experience across React, Next.js, and React Native.

## 🤝 How to Contribute

### 1. Check Existing Issues

Before starting work, review the existing GitHub issues to see whether your idea or bug has already been reported.

For significant changes, open an issue first to discuss your proposal with the maintainers.

### 2. Fork the Repository

Fork the Mintforge UI repository to your GitHub account, then clone your fork locally.

```bash
git clone https://github.com/YOUR-USERNAME/mintforge-ui.git
cd mintforge-ui
```

Replace `YOUR-USERNAME` with your GitHub username.

### 3. Install Dependencies

Install the project dependencies using npm.

```bash
npm install
```

### 4. Create a Branch

Create a separate branch for your contribution.

```bash
git checkout -b feat/your-feature-name
```

Use a descriptive branch name, such as:

* `feat/button-component`
* `fix/navigation-bug`
* `docs/installation-guide`

### 5. Make Your Changes

When contributing, please:

* Follow the existing project structure and coding conventions.
* Write clean, readable, and maintainable code.
* Keep components reusable and customizable.
* Maintain consistency with the Mintforge UI design system.
* Update documentation when your changes affect usage or behavior.
* Avoid introducing unnecessary dependencies.

### 6. Test Your Changes

Before submitting your contribution, run the available project checks.

```bash
npm run lint
npm run build
```

Fix any issues caused by your changes before opening a pull request.

### 7. Commit Your Changes

Use a clear and descriptive commit message.

```bash
git add .
git commit -m "feat: add your feature"
```

Examples:

* `feat: add button component`
* `fix: resolve card layout issue`
* `docs: improve setup instructions`

### 8. Submit a Pull Request

Push your branch to your fork.

```bash
git push origin feat/your-feature-name
```

Then open a pull request against the main branch of the original repository.

In your pull request, explain:

* What you changed.
* Why the change is needed.
* How you tested it.
* Any relevant screenshots for UI changes.

Your contribution will be reviewed before it is merged.

## 🎨 Component Contribution Guidelines

When contributing UI components or blocks:

* Prioritize accessibility and usability.
* Support responsive layouts where applicable.
* Follow the project's existing styling conventions.
* Provide clear examples of component usage.
* Keep customization straightforward.
* Avoid unnecessary complexity.

For React Native components, ensure that implementations are suitable for supported mobile platforms and follow React Native conventions.

## 📝 Documentation Contributions

Documentation improvements are welcome, including:

* Installation instructions.
* Component usage examples.
* API and prop explanations.
* Setup guides.
* Corrections to existing documentation.

Please keep documentation accurate, concise, and beginner-friendly.

## 🐛 Reporting Bugs

If you discover a bug, open an issue in the GitHub repository.

Include the following details whenever possible:

* A clear description of the problem.
* Steps to reproduce it.
* Expected and actual behavior.
* Relevant error messages.
* Screenshots or environment details, if applicable.

## 💡 Suggesting Features

We welcome ideas that improve Mintforge UI.

Before implementing a major feature, open an issue describing the problem, your proposed solution, and its potential benefits to developers.

## 📜 Code of Conduct

Be respectful, constructive, and inclusive when interacting with contributors and maintainers.

Harassment, personal attacks, discrimination, and abusive behavior are not acceptable.

## 🔐 Security Issues

Please do not report security vulnerabilities through public GitHub issues. Follow the instructions in `SECURITY.md` once the project's security policy is available.
